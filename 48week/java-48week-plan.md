## 一、每天固定 1 小时怎么用

每天不用自己纠结「今天到底看什么」。一周七天结构固定，只需要照着走。

| 星期 | 时间分配 | 做什么 |
| :--- | :--- | :--- |
| **周一** | 复习 10 + 学新 35 + 总结 15 | 理论输入，末尾关掉资料自己写一遍 |
| **周二** | 复习 10 + 写代码 40 + 记录 10 | 纯动手，记录踩坑 |
| **周三** | 复习 10 + 源码原理 35 + 画图 15 | 看源码，画调用链路图 |
| **周四** | 复习 10 + 做项目 45 + 记录 5 | 把本周知识塞进自己的项目 |
| **周五** | 复习 15 + 面试题 30 + 口述 15 | 口头讲出来，不背答案 |
| **周六** | 连续做项目 60 | 不看视频，只写代码 |
| **周日** | 回顾 20 + 重做错题 20 + 整理卡片 20 | 全部交给输出 |

**一周合计 420 分钟**

| 类型 | 分钟 | 占比 |
| :--- | ---: | ---: |
| 输入（复习 + 学新 / 源码） | 约 215 | 51% |
| 动手（写代码 + 做项目） | 145 | 35% |
| 输出（总结 + 记录 + 复盘） | 约 60 | 14% |

> 这样每天都是一小时，但不会变成「每天看一小时视频」。
> **输出那 14% 是最容易被砍掉、也最不能砍的部分。**

## 七、每天到底应该学多少

这是最重要的一点。

**1 小时不是：**

```text
60 分钟看视频
```

**而应该是：**

```text
10 分钟 复习
35 分钟 学习 / 写代码
15 分钟 输出
```

其中**「输出」必须保留**。

比如今天学 Spring 事务，最后 15 分钟关掉资料，自己写：

1. 事务是什么？
2. Spring 怎么实现？
3. `@Transactional` 为什么可能失效？
4. `REQUIRES_NEW` 做什么？
5. `this.xxx` 为什么可能失效？

> **如果你能自己回答，才算真的学会。**

## 九、最重要的学习规则

> **把工作中的 Bug 变成学习材料，是你效率最高的方式。**

以后工作遇到问题，**不要修完 Bug 就关掉 IDE**。

比如遇到：

```text
@Async 事务失效
```

修完以后，额外花 **20～30 分钟**问自己：

1. 为什么？
2. 底层原理是什么？
3. 还有哪些情况会失效？
4. 面试怎么问？
5. 我能不能写一个 Demo 复现？

> 你一天只有 1 小时，所以这一点尤其重要。
> 你之前碰到的事务、异步、MyBatis、SQL 优化这些问题，其实都非常适合这么学习。

## 十一、实际执行标准

### 每天只需要完成这 3 件事

1. **学一个知识点**
2. **写一点代码**
3. **留下一份自己的笔记**

哪怕当天只学会——

> 「为什么 `this.xxx()` 会导致 Spring 事务失效」

也算完成。

> **不要追求每天学很多，要追求 300 天后还能继续学。** ☕💻

### 20 条自查清单（每 4 周过一次）

**投入与坚持**

- [ ] 每天真的有 60 分钟投入，不是「计划了 60 分钟」
- [ ] 每天最后一件事是输出，不是关掉视频
- [ ] 没有连续 3 天断档
- [ ] 这 4 周的投入时间统计出来了（不是凭感觉）

**动手**

- [ ] 本周至少写了 2 小时代码
- [ ] 至少有一个知识点是自己动手验证过的，不是只看教程
- [ ] 至少完整读过一段源码，并画出了调用链路图
- [ ] 有 1 个自己造出来的问题现场（比如故意写慢 SQL、故意让事务失效）
- [ ] 遇到 Bug 后额外花了 20–30 分钟追问原理，而不是修完就关 IDE

**理解**

- [ ] 本周的知识点能脱稿讲出来至少 3 个
- [ ] 能说清这个知识点**解决了什么问题**，而不只是 API 怎么用
- [ ] 面试题是讲出来的，不是背出来的
- [ ] 有至少 1 次把知识讲给别人听（或对着录音讲一遍）
- [ ] 知道下一个月要学什么，以及为什么学它

**产出**

- [ ] 整理过至少 1 个踩坑记录
- [ ] 笔记里记的是自己的话，不是复制粘贴的原文
- [ ] 项目在推进，不是停在第一版
- [ ] 项目里新增的功能用到了这段时间学的东西
- [ ] 项目能一条命令跑起来（不做「本地能跑、别人跑不了」的项目）
- [ ] 如果现在去面试，能讲清楚项目里最有技术含量的那一块
