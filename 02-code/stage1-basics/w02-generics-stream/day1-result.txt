========== A · 运行时还有没有泛型？ ==========
strings.getClass() = java.util.ArrayList
ints.getClass()    = java.util.ArrayList
是同一个 Class 对象？ true
new Box<String>() 和 new Box<Integer>() 同一个类？ true
strings instanceof List ？ true
strings.getClass() == List.class ？ false   <- 泛型接口的实参也没了，只剩实现类
结论：泛型只活在编译器眼里，运行时的对象身上一个字节都没有。

========== B · 反射看到的签名长什么样 ==========
List 接口里所有 add 方法的擦除后签名：
  add(int, Object)
  add(Object)
  getMethod("add", String.class) -> NoSuchMethodException（没有这个方法）
  getMethod("add", Object.class)  -> public abstract boolean java.util.List.add(E)
Box 类声明上的类型变量：T（边界 java.lang.Object）
Box.get 的泛型返回类型：T
Box.set 的参数类型（反射 getParameterTypes）：Object
结论：擦掉的是「使用处填的实参」，声明处的类型变量 T 以元数据形式留在 class 文件里。

########## 2/3  PecsDemo · run.bat PecsDemo ##########

========== A · 泛型是不变的（invariant） ==========
List<Object> objs = strs;  编译错误：incompatible types
  （不是设计缺陷，是故意的：数组协变留下的坑，泛型用不变性补上）
对比：Object[] arr = new String[2]; arr[0] = 42; -> ArrayStoreException（运行时才发现）
复制一份之后 copied = [a, b, 42]，strs 仍然是 [a, b]

========== B · ? extends Number：只读 ==========
sum(List<Integer>) = 6.0
sum(List<Double>)  = 4.0
sum(List<Long>)    = 30.0
  签名是 sum(List<? extends Number>)，一个方法吃掉三种 List
读出来 1，静态类型 Number，实际 Integer
wild.add(null) 允许（null 是唯一对所有子类型都合法的值），size = 4
wild.add(4) 编译错误：? extends Number 可能是 Double，编译器不敢让你写
结论：extends 通配符 = 生产者，只能读；读出来的上界就是那个上界类型。

========== C · ? super Integer：只写 ==========
fill 到 List<Object>  -> [0, 1, 2]  元素实际类型 Integer
fill 到 List<Number>  -> [0, 1, 2]
fill 到 List<Integer> -> [0, 1, 2]
  签名是 fill(List<? super Integer>, int)，三种容器都能收
wild.add(7) 可以，nums 变成 [0, 1, 2, 7]；读出来静态类型只能是 Object -> 7（运行时是 Integer）
Integer bad = wild.get(0) 编译错误：容器可能是 List<Object>，里面不一定装 Integer
结论：super 通配符 = 消费者，只能写；读出来只能当 Object。

========== D · Collections.copy 的签名为什么长那样 ==========
copy(List<Object> dest, List<String> src) 之后 dest = [a, b, c]
  签名：<T> void copy(List<? super T> dest, List<? extends T> src)
  dest 是消费者 -> super；src 是生产者 -> extends；T 由两边共同推断出来

========== E · Stack 的 pushAll / popAll ==========
pushAll(List<Integer>) + pushAll(List<Double>) 之后 size = 5
popAll 到 Collection<Object> -> [2.5, 1.5, 3, 2, 1]
换成 Collection<Integer> 接 popAll 会编译错：栈里可能有 Double

========== 收尾 ==========
PECS：参数是「生产者」用 extends（只读），是「消费者」用 super（只写）。
没有通配符的 <T> 只能保证「进和出是同一种类型」，一旦要跨类型传，就得放开一端。
