########## 3/3  CollectorTraps · 收集器六个陷阱（D） ##########

========== D1 · toMap 的重复 key ==========
D1 id 唯一时正常 -> 15 条，取 U01 = 张伟
D1 换成以部门为 key（研发 5 人）：
D1   -> java.lang.IllegalStateException: Duplicate key 研发 (attempted merging values 22000 and 31000)
D1   注意它报在**收流那一刻**，栈里看不出是哪两条数据撞的 —— 这是 toMap 最难排查的地方
D1 修法一 (a, b) -> a 保留先出现的 -> {产品=26000, 研发=22000, 运营=15000, 测试=16000}
D1 修法二 Math::max 取最高 -> {产品=33000, 研发=45000, 运营=21000, 测试=17000}
D1 两个修法的区别不是「哪个对」，而是「业务要哪个」—— 写 (a,b)->a 之前一定要能说出「为什么丢掉 b 是可以的」

========== D2 · toMap 的 value 为 null ==========
D2 HashMap.put 一个 null value -> {何静=null}，没抛异常，size=1
D2 所以「HashMap 不能存 null」是错的 —— 它允许一个 null key + 任意多个 null value
D2 但 toMap 的 value 为 null（何静 / 徐丽 的 age 是 null）：
D2   -> java.lang.NullPointerException，message = <空>
D2   连一句解释都没有，栈顶还落在 Collectors 内部，只能靠「我传了 null value」自己想到
D2 原因：toMap 内部走的是 map.merge(key, value, mergeFunction)，而 HashMap.merge 第一句就是 if (value == null || remappingFunction == null) throw new NullPointerException()
D2 换句话说：toMap 用的是 merge，不是 put；put 的宽松规则在 merge 这儿被收紧了
D2 修法一：value 侧换成 String.valueOf(age)（null 变字面量 "null"）-> 15 条
D2 修法二：提前 filter(u -> u.age() != null)，代价是「没年龄的人」整条消失
D2 选哪个取决于语义：是「这个人不存在」还是「这个人存在但年龄未知」

========== D3 · groupingBy 的 key 为 null ==========
D3 全量 15 条里，U99 的 dept 是 null：
D3   -> java.lang.NullPointerException: element cannot be mapped to a null key
D3 groupingBy 内部对 classifier 的返回值做了 Objects.requireNonNull，所以它连一个「null 组」都不给你
D3 三种应对：① filter 掉；② classifier 里映射成 "未分配"；③ 换成 groupingBy(u -> Optional.ofNullable(u.dept()), ...) —— 但这会把 Optional 塞进 Map 的 key 里，而 Optional 的 equals 是值语义，能当 key，只是可读性很差，不推荐
D3 对比 D2：同一个「按 key 聚合」，两者的 null 政策居然不一样 —— 先看 toMap 拿 dept 当 key（含那条 null）：
D3   toMap -> {null=50000}，没抛异常，null 成了一个正经的 key
D3 因为 toMap 走 HashMap.merge，而 HashMap 允许一个 null key；groupingBy 则用 Objects.requireNonNull 把 null 挡在门外

========== D4 · teeing：一次遍历算两个聚合 ==========
D4 两遍流 -> 总额 374500，人数 15，人均 24966.7
D4 teeing 一遍流 -> 人均 24966.7
D4 teeing(downstream1, downstream2, merger)：两个下游并行喂同一个元素，最后 merger 把两个结果合成一个值
D4 嵌套 teeing 一次拿三个指标 -> 总额 374500，人数 15，最高 50000
D4 groupingBy + teeing（每组人均薪资）-> {产品=27667, 研发=27600, 运营=18333, 测试=16167}
D4 teeing 是 JDK 12 新增，JDK 8 项目里只能用 collectingAndThen 套一个自定义累加器，或者老老实实跑两遍 —— 面试问「怎么一遍流求平均」就从这儿答

========== D5 · 三种 toList 的可变性 ==========
D5 Collectors.toList() -> java.util.ArrayList
D5 Stream.toList()（JDK 16+）-> java.util.ImmutableCollections$ListN
D5 Collectors.toUnmodifiableList() -> java.util.ImmutableCollections$ListN
D5 依次尝试 add("X")：
D5   Collectors.toList()        -> 成功（可变），size=16
D5   Stream.toList()            -> UnsupportedOperationException
D5   toUnmodifiableList()       -> UnsupportedOperationException
D5 还有第三个差异：允许 null 元素吗（用一条含 null 的流去撞，而不是往结果里 add）
D5   Collectors.toList()        -> 允许（size=2，实现 ArrayList）
D5   Stream.toList()            -> 允许（size=2，实现 ListN）
D5   Collectors.toUnmodifiableList() -> NullPointerException（拒绝 null 元素）
D5   注意这里三选二不是一致的：Stream.toList() 和 toUnmodifiableList() 返回同一族不可变实现（ImmutableCollections$ListN），但前者**放行 null**、后者**拒绝 null**
D5   原因在实现路径：Stream.toList() 走 listFromTrustedArrayNullsAllowed，toUnmodifiableList() 走 listFromTrustedArray —— 后者逐个 Objects.requireNonNull
D5   而 List.of("a", null) 是 NPE：那是「多个固定实参」的重载，跟单传一个数组的行为不一样
D5 结论：Collectors.toList() 只承诺「是个 List」，实现类和可变性都没承诺；JDK 16 的 Stream.toList() 明确不可变，但**不拒绝 null 元素**（这条最容易记反）
D5 项目里混用过的典型事故：方法返回 Stream.toList() 的结果，调用方一句 .add() / .sort() 就 UnsupportedOperationException —— 而且**只在线上数据走到那行时**才炸

========== D6 · 一对多：toMap 硬扛 vs groupingBy ==========
D6 toMap + 合并函数 -> {产品=[刘洋(26000), 陈静(24000), 郑凯(33000)], 研发=[张伟(22000), 李娜(31000), 王强(18000), 周涛(45000), 何静(22000)], 运营=[杨帆(15000), 赵敏(19000), 孙浩(21000)], 测试=[吴磊(16000), 徐丽(17000), <null>(15500)]}
D6 groupingBy + mapping -> {产品=[刘洋(26000), 陈静(24000), 郑凯(33000)], 研发=[张伟(22000), 李娜(31000), 王强(18000), 周涛(45000), 何静(22000)], 运营=[杨帆(15000), 赵敏(19000), 孙浩(21000)], 测试=[吴磊(16000), 徐丽(17000), <null>(15500)]}
D6 结果一样，但 toMap 那版你得自己 new ArrayList、自己 addAll、还得担心合并顺序；groupingBy 一行就说完「按部门把 brief 收成 List」
D6 判断口诀：key 唯一 -> toMap；key 会重复 -> groupingBy。用 toMap 处理重复 key，等于用手动合并函数重新实现一遍 groupingBy

========== D 收尾 ==========
这六条的共同点：**编译期一句都不报，全靠运行时**。
toMap 用之前先问自己两句：key 会不会重复？value 会不会是 null？
