========== 实验 A：hash 低 4 位相同、第 5 位不同 → 会拆 ==========
4 个 key 的 hash 选成 0x00 / 0x10 / 0x20 / 0x30（低 4 位全是 0）

-- 容量 16（n-1 = 0b1111，只看低 4 位）--
   k0(hash=0x0)  →  桶 0
   k1(hash=0x10)  →  桶 0
   k2(hash=0x20)  →  桶 0
   k3(hash=0x30)  →  桶 0
   4 个 key 全挤在桶 0（因为低 4 位都是 0）

-- 再塞 9 个普通 key，size = 13 → 触发扩容 --
  扩容后容量 = 32（n-1 = 0b11111，第 5 位开始参与）

   k0(hash=0x0)       → 桶 0   （hash & 16 == 0  → 留）
   k1(hash=0x10)      → 桶 16  （hash & 16 == 16 → 走）
   k2(hash=0x20)      → 桶 0   （hash & 16 == 0  → 留）
   k3(hash=0x30)      → 桶 16  （hash & 16 == 16 → 走）

   桶 0 被拆成了两条链：k0 / k2 留在桶 0，k1 / k3 搬到桶 16。
   搬家的规则就是把原来那条链按「第 5 位是 0 还是 1」劈成两半。

========== 实验 B：hash 完全相同 → 不会拆 ==========
用 hashCode 恒为 0 的 key，塞 11 个：

   第 1   个：容量 16    size 1    它落在桶 0
   第 2   个：容量 16    size 2    它落在桶 0
   第 3   个：容量 16    size 3    它落在桶 0
   第 4   个：容量 16    size 4    它落在桶 0
   第 5   个：容量 16    size 5    它落在桶 0
   第 6   个：容量 16    size 6    它落在桶 0
   第 7   个：容量 16    size 7    它落在桶 0
   第 8   个：容量 16    size 8    它落在桶 0
   第 9   个：容量 32    size 9    它落在桶 0   ← 扩容 16 → 32
   第 10  个：容量 64    size 10   它落在桶 0   ← 扩容 32 → 64
   第 11  个：容量 64    size 11   它落在桶 0

   注意：容量一路 16 → 32 → 64 在涨，但元素**始终在桶 0**，从没拆开过。

   原因：扩容不改变元素的 hash，只是让**更多位**参与下标计算。
        hashCode 恒为 0 → 扰动后 hash 还是 0 → 高位全是 0 →
        新增的位永远是 0 → (n-1) & 0 永远是 0 → 永远落桶 0。
