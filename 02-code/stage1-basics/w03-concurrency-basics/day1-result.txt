########## 一、StartThread（三种起线程方式 + run/start + daemon）##########

main 线程：Thread[main,5,main]，priority=5，daemon=false
可用核数：12

========== A · 方式一：extends Thread ==========
  [main] start() 之后，我看到的 state=RUNNABLE
  [extends] 线程名=worker-extends，id=15，state=RUNNABLE
  [main] join 回来，state=TERMINATED（执行完就是 TERMINATED）

========== B · 方式二：implements Runnable ==========
  [runnable] 线程名=worker-runnable，id=16
  [lambda] 线程名=worker-lambda（Runnable 是函数式接口，所以 lambda 能直接塞进 Thread）

========== C · 方式三：Callable<V>（有返回值）==========
  Runnable.run() 返回 void、不能抛受检异常；Callable.call() 两样都行。
  [main] get() 之前 isDone=false，此刻去 get() 会阻塞
  [callable] 在 worker-callable 上算完 1..100
  [main] get() 回来：5050，isDone=true
  [main] 抓到 java.util.concurrent.ExecutionException: java.lang.IllegalStateException: call() 里抛的异常会被包进 ExecutionException，真正的异常在 e.getCause() = java.lang.IllegalStateException: call() 里抛的异常会被包进 ExecutionException
  → 注意：原始异常不会直接冒泡出来，get() 统一包成 ExecutionException

========== D · run() 和 start() 不是一回事 ==========
  直接调 t.run()：
  [extends] 线程名=main，id=1，state=RUNNABLE
  ↑ 打印的是 main —— run() 只是普通方法调用，压根没开新线程
  第二次 start()：java.lang.IllegalThreadStateException（而且没有 message —— 别指望它告诉你为什么）
  [twice] 我在 worker-twice

========== E · 守护线程拦不住 JVM 退出 ==========
  [main] worker-daemon 的 daemon=true，main 立刻结束、不等它
  → 正常情况下，上面那句「5 秒到了」永远不会出现：JVM 只等非守护线程

========== C4 · 可见性：volatile 真正管的那件事 ==========
  一个线程死等标志位，主线程确认它已经在转，再等 50ms 才置 true。
  先普通 boolean，再 volatile。自旋上限 20 亿次，防止真的挂死；两次都用守护线程收尾。
  [普通 boolean] 自旋 2,000,000,000 次，✗ 一直到撞上 20 亿次上限都没看见，耗时 384 ms，线程还活着=false
  [volatile boolean] 自旋 198,178,635 次，在循环里看见了新值 ✓，耗时 51 ms，线程还活着=false
  说明：可见性问题在 x86 上本来就不容易复现 —— 没复现 ≠ 安全。
        「永远看不到」的物理来源通常是 JIT 把读操作提到循环外（编译期就把 field 读成了寄存器）。

========== 收尾 ==========
同一件事的三种说法，说的是同一件事：
  1. count++ 是 read-modify-write，三步之间随时可能被切走；
  2. 「原子性」和「可见性」是两个独立问题：volatile 只解决后者，synchronized 两个都解决；
  3. AtomicInteger 用 CAS 只解决「这一个变量」的原子性，多字段还是一个整体动作时仍要锁。
