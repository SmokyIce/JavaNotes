== S4 注入进来的 self 到底是什么 ==
  self 类名 = jdk.proxy2.$Proxy22
  self 与容器 bean 同类 = true
  self == 容器 bean      = false
  -> 同类不算证据：JDK 代理类按「接口组合」缓存，两个不同的代理完全可以共用同一个 $Proxy。
  self 的 TargetSource 类 = org.springframework.context.annotation.ContextAnnotationAutowireCandidateResolver$1
  self 的 target 类       = jdk.proxy2.$Proxy22
  self 的 target == bean  = true
  -> TargetSource 这一层才分得清：

     它 resolve 出来的正是容器里那个 AOP 代理 —— 所以真实链路是
     @Lazy 解析代理 → AOP 代理 → GreetingImpl 真身，三层。
     不加 @Lazy 就是「自己注入自己」的循环依赖，构造器注入会直接 BeanCurrentlyInCreationException

  -> 这是「配了没生效」的典型：@EnableAspectJAutoProxy 少了 exposeProxy=true，

== S6 三行代码的数字对照 ==
  this.hi()                       before=1  （外层 1 次，内层 0 次）
  self.hi()   （@Lazy 注入自己）  before=2
  currentProxy().hi()             before=2
  -> 三种写法业务结果一模一样，差别只在「有没有回到代理」。
     这就是为什么 @Transactional 在同类方法调用里静默失效：事务也是靠代理开闭的。

一句话：代理不会跟着 this 走 —— 谁拿着代理引用调方法，谁才有切面。
