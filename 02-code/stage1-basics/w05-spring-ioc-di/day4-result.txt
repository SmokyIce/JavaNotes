################ 2/3  CollectionInject ################

=== A. List<PayChannel>：顺序由 @Order 决定 ===
  注册顺序 = alipay, wechat, unionpay；@Order = wechat(1) < alipay(2) < unionpay(3)
  List 实际顺序 = wechat alipay unionpay 
  结论：List 按 @Order 排（wechat → alipay → unionpay），不是注册顺序
  PayChannel[] 实际顺序 = wechat alipay unionpay   ← 数组和 List 同源，排序也一致
  Map 实际顺序 = alipayChannel=alipay wechatChannel=wechat unionPayChannel=unionpay 
  ↑ 注意 Map 的顺序跟 List 不一样 —— 这一格是这一段的重点，见 B。

=== B. Map<String, PayChannel>：key 是谁，顺序听谁的 ===
  key 集合 = [alipayChannel, wechatChannel, unionPayChannel]
  key 是 bean 名（类名首字母小写），不是类全名、也不是 tag() 的返回值。
  顺序 = [alipayChannel, wechatChannel, unionPayChannel] ← 注册顺序，@Order 在这里没生效
  而同一个容器里的 List 是 wechat → alipay → unionpay ← @Order 生效了
  所以「按顺序执行一串策略」必须用 List；Map 只适合按名字精确取。

=== C. 容器里一个 PayChannel 都没有 ===
  C1. @Autowired（默认 required=true）List<PayChannel>：
      NoSuchBeanDefinitionException:
        No qualifying bean of type 'java.util.List<com.newt.java48.w05.day4.pay.PayChannel>' available: expected at least 1 bean which qualifies as autowire candidate. Dependency annotations: {@org.springframework.beans.factory.annotation.Autowired(required=true)}
      ↑ 注意类型写的是 List<PayChannel>，报的却是「至少要有 1 个」—— 集合没有特权。

  C2. @Autowired(required=false) List / Map：
      List → null（不是空集合！）
      Map  → null（不是空 Map！）
      所以「收成集合就天然为空」是假的：要么 required=false 后再判 null，要么写 `orElse(emptyList)`。

  C3. 同样空容器里注入单值 PayChannel：
      NoSuchBeanDefinitionException:
        No qualifying bean of type 'com.newt.java48.w05.day4.pay.PayChannel' available: expected at least 1 bean which qualifies as autowire candidate. Dependency annotations: {@org.springframework.beans.factory.annotation.Autowired(required=true)}
      跟 C1 是同一个异常类型 —— 集合和单值在「没有候选」这一点上没有区别。

=== D. 集合 + @Qualifier：缩范围而不是挑一个 ===
  @Qualifier("alipayChannel") List<PayChannel> → alipay
  候选按 qualifier 先缩到 1 个，再「收全部」—— 所以只剩 alipay，不会报 NoUnique。

################ 3/3  CtorInject ################

=== A. 单构造器：不写 @Autowired 也能注入 ===
  构造器上没有任何注解 → notifier = log
  Spring 4.3 起：类里只有一个构造器时它就是唯一的候选，不用标。
  这也是「构造器注入」被推荐之后，代码里 @Autowired 越来越少的原因。

=== B. 多构造器，一个都不标 ===
  B1. 没有无参构造器：
      BeanCreationException: Error creating bean with name 'ctorInject.TwoNoMark': Instantiation of bean failed; nested exception is org.springframework.beans.BeanInstantiationException: Failed to instantiate [com.newt.java48.w05.day4.CtorInject$TwoNoMark]: No default constructor found; nested exception is java.lang.NoSuchMethodException: com.newt.java48.w05.day4.CtorInject$TwoNoMark.<init>()
      ↑ 根因是 NoSuchMethodException: com.newt.java48.w05.day4.CtorInject$TwoNoMark.<init>()

  B2. 有无参构造器（同样一个都不标）：
      实际走的是「无参构造器」—— 不报错，参数版被静默忽略
      这个比报错危险：依赖是 null（或字段没赋上），运行时才 NPE。

=== C. 多构造器 + 标一个 @Autowired ===
  实际走的是「ctor(Notifier, String)  ← 被 @Autowired 选中」
  规则：多构造器时，标了 @Autowired 的那个赢；标了多个会报错。

=== D. ObjectProvider：把「取」推迟到调用时 ===
  D1. 容器里只有一个 prototype 的 PayChannel：
      provider.getObject() 两次 → temp-1 / temp-2
      是同一个对象吗：false（原型，所以每次都是新的）
      关键：注入的是「取的对象」不是「值」—— 容器此时并没有解析 PayChannel。

  D2. 容器里一个 PayChannel 都没有：
      getIfAvailable() → null
      getIfUnique()    → null
      getObject()      → NoSuchBeanDefinitionException: No qualifying bean of type 'com.newt.java48.w05.day4.pay.PayChannel' available: expected at least 1 bean which qualifies as autowire candidate. Dependency annotations: {@org.springframework.beans.factory.annotation.Autowired(required=true)}

  D3. 容器里有 3 个 PayChannel（就是 A 段让 @Autowired 爆炸的那种局面）：
      getIfUnique()  → null（多个候选 → null，不抛）
      getIfAvailable() → NoUniqueBeanDefinitionException（注意：它没兜住多候选）
      两种方法只差一个 if：Unique 会把 NoUnique 吞成 null，Available 不会。

=== E. 同一个「按名字回退」，换成构造器参数就不灵了 ===
  反射读到的参数名 = arg0（isNamePresent=false）
  javac 没加 -parameters/-g，参数名只剩 arg0 —— 拿它去和 bean 名对，当然对不上。
  结果：NoUniqueBeanDefinitionException: No qualifying bean of type 'com.newt.java48.w05.day4.pay.PayChannel' available: expected single matching bean but found 3: alipayChannel,wechatChannel,unionPayChannel
  对照 InjectionChoice 的 B 段：字段名 wechatChannel 什么都不写就能注入。
  差别不在「按不按名字」，在「名字拿不拿得到」。
