### 2. 挖到的三个反直觉点（可复用素材）
1. 随机 int key 下手写版比 JDK 快 0.6 倍 → 微基准单次数字无意义。
2. **hash 全等 + key 不可比较 → JDK HashMap 比手写链表慢 6.7 倍**（2 万条：2521ms vs 374ms）。
   源码依据 JDK17 `putTreeVal`：`if (!searched) { ch.find(h,k,kc) }` 对整个子树全扫；
   `tieBreakOrder` 用 identityHashCode 定序，和 equals 无关。
3. 同一个 key 加 `implements Comparable` → JDK 变 44ms（快 12 倍）。
   **结论：「链表到 8 个转红黑树」缺两个前提：容量 ≥ 64、key 能比较大小。**
