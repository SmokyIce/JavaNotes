## 三条实测结论（以后讲收集器直接用）

1. **`Predicate` 的 `or().and()` 是左结合 `(a||b)&&c`**，不是布尔优先级的 `a||(b&&c)`。
   同一份数据 `isDev.or(isTest).and(active)` = 6 人，`isDev.or(isTest.and(active))` = 7 人。
   这类错不报编译错、只少数据。
2. **`toMap` 走 `HashMap.merge` 不是 `put`**：value 为 null 抛**无 message** 的 NPE（而 `put(k,null)` 没问题）；
   key 为 null 反而允许（`{null=50000}`）。`groupingBy` 则 `requireNonNull` 拒绝 null key。
3. **「不可变」≠「不许 null」**：`Stream.toList()` 和 `toUnmodifiableList()` 返回同一个
   `ImmutableCollections$ListN`，但前者放行 null（`listFromTrustedArrayNullsAllowed`）、
   后者拒绝（`listFromTrustedArray`）。
4. **方法引用与 lambda 的 NPE 信息量不同**：`averagingInt(User::age)` 的拆箱 NPE **message 为空**，
   换成 `averagingInt(u -> u.age())` 就有 `Cannot invoke "Integer.intValue()" because ... "User.age()" is null`。
   原因是方法引用的拆箱在 lambda metafactory 的 MethodHandle 适配层，没有字节码位置可指。
