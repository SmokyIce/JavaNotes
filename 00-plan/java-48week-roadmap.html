四条执行铁律

1输入必须留 15 分钟

学完 Spring 事务，关掉资料自己写：事务是什么 / Spring 怎么实现 / @Transactional 为什么失效 / REQUIRES_NEW 做什么 / this.xxx() 为什么失效。能自己答出来，才算学会。

2Bug 修完别关 IDE

修完 @Async 事务失效后，再花 20–30 分钟问自己：为什么？底层原理是什么？还有哪些情况会失效？面试怎么问？能不能写个 Demo 复现？

3项目从第 8 周开始长

异步任务管理平台：创建 / 执行 / 进度 / 失败 / 重试 / 取消 / 日志 / 恢复。后面 40 周不断往里加 Redis、MQ、Docker、微服务，避免"学了一堆技术但没有一个完整项目"。

4追求 300 天后还在学

不要追求每天学很多。哪怕当天只搞懂"为什么 this.xxx() 会导致 Spring 事务失效"，也算完成。持续性压倒强度。

今天的最小完成标准

① 学一个知识点 ② 写一点代码 ③ 留下一份自己的笔记。三件事做完，这一天就成立了。
